## 1. 같은 이름의 응답 모델 때문에 프런트엔드 타입이 깨짐

**증상**
게임 API(`backend/app/game.py`)를 추가한 뒤 `npm run gen:api` 로 프런트 타입을 다시 만들었더니, 기존에 쓰던 응답 타입 이름이 바뀌어 프런트엔드의 타입 참조가 깨졌다.

**원인**
`game.py` 에 만든 응답 모델 이름(`CharacterOut`, `MeOut`, `PhaseOut`, `ConfirmIn` 등)이 `characters.py`, `confirm.py` 의 모델 이름과 겹쳤다. FastAPI 는 OpenAPI 스키마에서 이름이 겹치는 모델을 모듈 경로를 붙여 구분하므로(`app__game__CharacterOut`, `app__characters__CharacterOut`), 생성된 `schema.d.ts` 의 이름이 `CharacterOut` 에서 `app__…__CharacterOut` 으로 바뀌었다.

**해결**
게임 쪽 모델 이름에 `Game` 접두사를 붙여 이름이 겹치지 않게 했다(`GameMemberRef`, `GameMeOut`, `GamePhaseOut`, `GameCharacterOut` 등). 스키마를 다시 생성하자 모듈 경로가 붙은 이름이 사라지고 `GameCharacterOut` 처럼 안정적인 이름이 되었다.

**확인**
`npm run gen:api` 후 `npm run typecheck` 가 통과한다. 백엔드 API 가 바뀌면 이 두 명령을 함께 돌리고 `src/api/schema.d.ts` 를 같이 커밋한다(README 「API 타입 생성」).

## 2. 페이즈 카드를 끌기 시작할 때 다른 카드가 순간적으로 밀림

**증상**
시나리오 제작 화면의 흐름 탭에서 페이즈 카드를 마우스로 끌기 시작하면, 끌지 않는 다른 카드가 순간적으로 엉뚱한 자리로 밀렸다. 카드의 오른쪽 절반을 잡았을 때 두드러졌다.

**원인**
끌기가 막 시작된 첫 움직임에는 화면이 아직 "제자리 표시"로 바뀌기 전이다. 이 시점에 끌고 있는 카드 자신이 "놓일 자리" 계산 대상에 포함되어, 자기 뒤의 자리가 엉뚱한 자리로 읽혔다.

**해결**
위치를 판정할 때 끌고 있는 카드를 번호로 걸러 냈다(`frontend/src/workspace/useFlowDrag.ts`). 같은 문제가 다시 생기지 않도록 브라우저 시험 `e2e/flow_drag.mjs` 를 추가했다.

**확인**
`e2e/flow_drag.mjs` 는 두 가지를 확인한다. 끌기를 시작하는 순간 다른 카드가 밀리지 않는지, 실제로 옮기면 순서가 바뀌는지(실행법은 `e2e/README.md`).

## 3. AI 테스트 플레이어가 인물을 고르지 못하는데 로그에는 "성공"으로 보임

**증상**
AI 테스트 플레이어를 방에 입장시켰는데, 캐릭터 선택 단계에서 인물이 배정되지 않았다. 그런데 터미널 로그에는 요청이 성공한 것처럼 나왔다.

**원인**
확인된 것: 서버가 HTTP 200 으로 응답해도 요청한 일이 받아들여졌다는 뜻이 아니었다(선택이 거부되었는데도 응답 코드는 200). 플레이어가 응답 본문을 읽지 않고 200 이면 성공으로 기록해서, 로그만 보고는 실패를 알 수 없었다.
함께 점검해 보강한 것: 모델 출력 길이 한도, 도구 입력 스키마의 복잡도, 모델이 돌려주는 값의 형식(문자열·숫자) 불일치. 이 중 어느 것이 그때의 직접 원인이었는지는 기록으로 확정하지 못했다.

**해결**
- 응답 본문을 해석해 거부되면 "받아들여지지 않음 → 사유"를 출력한다.
- 모델 출력 한도를 4096 토큰으로 올리고, 도구 입력 스키마를 단순화하고, 받은 값을 필요한 형식으로 변환한다.
- 해야 할 일이 남아 있으면 최소 8초 간격으로 다시 시도한다.
- 위 동작을 `backend/tests/test_ai_players.py` 에 시험으로 남겼다.

**확인**
`pytest backend/tests/test_ai_players.py`. 이후 실제 Claude 모델로 실행했을 때 인물 선택이 이루어졌다(소규모 4인 실행에서만 확인).

## 4. AI 호출이 400 오류로 반복 실패하고 멈춤

**증상**
AI 4명이 게임을 하던 중 갑자기 모두 멈췄고, 터미널에 HTTP 400 오류가 계속 출력되었다.

**원인**
코드 오류가 아니었다. 오류 본문이 Anthropic 계정의 크레딧 잔액 부족을 알리고 있었다. 이전에는 이런 실패에도 같은 간격으로 계속 호출을 시도해서 오류만 쌓였다.

**해결**
- 호출이 실패하면 5초부터 두 배씩(최대 120초) 쉬었다 다시 시도하는 백오프를 넣고, 잔액 부족이면 충전 안내 문구("Plans & Billing 에서 크레딧을 충전하세요"), 인증 오류면 키 확인 안내를 출력한다.
- 잔액이 예상보다 빨리 줄어, 기본 모델을 더 저렴한 `claude-haiku-5-5` 로 바꾸고 생각 깊이를 `low` 로 두었다(`MM_AI_MODEL`, `MM_AI_EFFORT` 로 바꿀 수 있다).
- AI 한 명이 모델을 부르는 최소 간격을 8초로 두고(`--think`), 시스템 프롬프트에 캐시(`cache_control`)를 적용했으며, 사용량 집계에 캐시 쓰기를 포함했다.

**확인**
실행 로그의 사용량 줄에서 호출 수와 토큰을 볼 수 있다. 실제 비용은 모델·인원·진행 시간에 따라 달라지며, 이 저장소에는 측정한 비용 기록이 없다.

## 5. 모두 확인·선택·투표를 마쳐도 다음 단계로 넘어가지 않음

**증상**
"시간이 끝나면 자동으로 넘기기"를 켜 두었는데, 모든 플레이어가 확인을 누르거나 인물을 고르거나 투표를 마쳤는데도 시간이 끝나거나 방장이 직접 넘길 때까지 다음 단계로 가지 않았다.

**원인**
자동 진행이 시간 만료만 판정했다(`Game.auto_advance_if_due`). 단계마다 "모두 끝났는가"라는 조건이 엔진에 없었다.

**해결**
단계의 완료를 판정하는 `cards.phase_completion(game)` 을 추가했다(읽기 단계는 전원 확인, 인물 선택은 전원 선택, 투표는 전원 투표). 자동 진행이 시간 만료와 함께 이 판정을 사용하며, 옵션 이름은 "자동으로 넘기기"로 바꿨다. 일시정지 중, 시간 제한 없음, 마지막 단계, 종료된 게임은 넘기지 않는다.

**확인**
`pytest backend/tests/test_auto_advance_completion.py`.

## 6. 기능을 더한 뒤 브라우저 시험이 조용히 낡아 실패함

**증상**
문서를 정리하려고 브라우저 시험(`e2e/`) 3개를 다시 돌렸더니, `first_flow.mjs` 는 오류로 중간에 멈췄고 `full_flow.mjs` 는 세 번 중 한 번 실패했다. 자동 시험(pytest, vitest)은 모두 통과하던 상태였다.

**원인**
제품 코드의 문제가 아니라 시험 코드가 뒤처져 있었다. 세 가지가 겹쳤다.
1. 채팅 패널이 생기면서 "전체 방장님, 의사, 셋째" 같은 장소 버튼이 생겼고, 인물 버튼을 `getByRole("button", { name: /의사/ })` 로 찾던 시험이 두 요소와 맞아 Playwright 의 엄격 모드 오류로 멈췄다.
2. 엔진의 `글()` 인자 순서가 `글(이름, 내용)` 으로 바뀌었는데, 시험 안의 스크립트는 옛 순서 `글(내용, 이름)` 이었다. 그래서 탭 본문이 "공통 스토리"라는 글자만 보였고 "탭으로 남아 있다" 확인이 실패했다. 이전 단계의 확인은 제목 자리에 이야기가 들어가 우연히 통과하고 있었다.
3. 투표 후 "1/3" 확인이 타이밍에 의존했다. "투표 완료" 칸은 처음부터 있어서, 숫자가 바뀌기 전에 읽으면 가끔 실패했다.

**해결**
인물 버튼을 `locator("button.choice", { hasText })` 로 좁혀 찾고, 시험 스크립트의 `글()` 인자 순서를 고치고, 숫자가 나타날 때까지 기다리도록 바꿨다.

**확인**
수정 후 세 스크립트가 모두 통과한다(`first_flow` 18, `full_flow` 31, `flow_drag` 4개 확인). 이 저장소에는 CI 가 없어서 기능을 더할 때 브라우저 시험을 함께 돌리지 않으면 같은 일이 다시 생길 수 있다.
