# 개인 확장 과제: 근감소증 진단 시스템 풀스택 구현

## 1. 과제 배경

지금까지 진행한 연구(2D 걷기 영상 → 3차원 골격 데이터 추출 → EfficientGCN 모델을 통한 근감소증 진단)는 논문으로 정리되어 학술대회에서 발표까지 마쳤습니다.

이번 과제의 목표는 이 연구 결과를 **실제로 동작하는 웹 시스템**으로 확장하는 것입니다. 즉, "논문을 썼다"에서 "동작하는 시스템을 만들었다"로 포트폴리오의 무게중심을 옮기는 작업입니다.

---

## 2. 전체 아키텍처

```
[골격 좌표 데이터]
        │
        ▼
   FastAPI (추론 서버) ──────► PostgreSQL (데이터/결과 저장)
        │                            ▲
        ▼                            │
  EfficientGCN 모델            (진단 이력 조회)
        │
        ▼
   React 프론트엔드
   - 스켈레톤 애니메이션 뷰어
   - 진단 결과 카드
   - 모델 정확도 대시보드

전체 → Docker Compose로 컨테이너화 (backend / frontend / db)
```

---

## 3. 단계별 과제

### 1단계 — 데이터베이스 & API 골격

**PostgreSQL 테이블 설계**

| 테이블 | 주요 컬럼 | 용도 |
|---|---|---|
| `subjects` | id, age, gender, group, memo | 피험자 메타데이터 |
| `gait_recordings` | id, subject_id(FK), video_path, recorded_at, frame_count | 촬영 원본 정보 |
| `skeleton_sequences` | id, recording_id(FK), joint_data, extraction_model | 프레임별 관절 좌표 시퀀스 |
| `diagnoses` | id, recording_id(FK), predicted_label, verified_label, confidence, model_version, created_at | 진단 결과 |

> **핵심 설계 포인트**: `predicted_label`(모델이 예측한 값)과 `verified_label`(나중에 연구자가 확인/수정한 값)을 **반드시 분리 저장**합니다. 하나로 합치면 나중에 "모델이 얼마나 정확했는지"를 계산할 수 없게 됩니다.

**FastAPI 엔드포인트**

- `POST /subjects` — 피험자 등록
- `POST /recordings/{subject_id}` — 골격 데이터 업로드
- `POST /diagnoses/{recording_id}/predict` — 모델 추론 실행 → 결과 저장
- `GET /diagnoses/{recording_id}` — 진단 결과 조회
- `GET /subjects/{id}/history` — 피험자별 진단 이력 조회

### 2단계 — 모델 서빙

- 서버 시작 시(`lifespan` 이벤트)에 모델을 **1회만 로딩**해서 `app.state`에 보관
- 요청마다 모델을 다시 불러오지 않도록 주의 (성능 이슈로 이어짐)

### 3단계 — 프론트엔드 (React + Vite)

정규 수업에서 다루지 않은 스택이므로, React 공식 튜토리얼과 Canvas API(MDN 문서)를 참고해 자기주도로 학습하며 진행합니다. 막히는 부분은 언제든 질문 가능합니다.

- **스켈레톤 애니메이션 뷰어**: 저장된 관절 좌표 시퀀스를 `<canvas>`에 프레임 단위로 그려서 재생 (재생/일시정지 컨트롤 포함). 관절 점을 찍고 인체 구조에 맞게 선으로 연결해서, 프레임을 순서대로 넘기면 "걷는 막대인간"처럼 보이게 만드는 것이 목표입니다.
- **진단 결과 카드**: `predicted_label`, `confidence`를 화면에 표시
- **모델 정확도 대시보드**: `/admin/model-accuracy` 엔드포인트와 연동한 차트

### 4단계 — 모델 모니터링

- `GET /admin/model-accuracy`: `verified_label`이 채워진 건수 대비 `predicted_label`과 일치하는 비율을 계산해서 반환
- `ml/retrain.py`: `verified_label` 데이터가 쌓이면 이를 활용해 모델을 재학습하는 스크립트 (서버 코드와는 분리된 별도 스크립트로 작성)

### 5단계 — Docker 컨테이너화

- `docker-compose.yml`로 `backend`(FastAPI) / `frontend`(React) / `db`(PostgreSQL) 3개 서비스 구성
- `docker compose up` 한 줄로 전체 시스템이 기동되는 상태를 목표로 함
- PostgreSQL 데이터가 컨테이너 재시작 후에도 유지되도록 volume 설정 필수

### 6단계 (선택, 여유 있으면) — 테스트 & CI

- `pytest`로 핵심 엔드포인트(업로드, 추론, 조회) 테스트 작성
- GitHub Actions로 push 시 테스트 자동 실행
